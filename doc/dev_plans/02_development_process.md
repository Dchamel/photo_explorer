## Главные правила (ОБЯЗАТЕЛЬНЫ)

### Правило 1. Сначала окружение, потом код
Код НЕ начинаем, пока заказчик не подтвердит, что установил и проверил:
- Rust (`rustc --version`, `cargo --version` работают);
- Visual Studio Build Tools (C++);
- расширение `rust-analyzer` в VS Code.

### Правило 2. Стоп после каждого этапа
После завершения каждого этапа разработки ОБЯЗАТЕЛЬНО:
1. **Коммит, затем пуш — РАЗДЕЛЬНЫМИ командами.** Не склеивать в одну строку через `&&`.
   После `git push` выполнить `git status` и убедиться в сообщении «up to date with 'origin/main'» —
   это доказательство, что коммит реально улетел на GitHub. Так молчаливый сбой пуша не останется незамеченным.
2. **Инструкция по ручному тестированию.** Архитектор пишет заказчику пошагово, КАК лично проверить результат этапа (какие команды выполнить, что должно появиться на экране).
3. **Ждём подтверждения заказчика**, что этап проверен и принят. Только потом двигаемся дальше.

### Правило 3. Принципы кода
Весь код пишется по **SOLID / DRY / KISS** с осознанным применением паттернов (см. архитектурный план, раздел 8).

### Правило 4. Модульность и тесты
- Каждый модуль — в своей папке.
- Для каждого модуля — автотесты в папке `tests/`.
- В корне проекта только: `main.rs`-запускник (через `src/`), `Cargo.toml`, `README.md`, `.gitignore` и важные конфиги.

### Правило 5. Документация ведётся на русском
Все планы и пояснения — в `doc/`. Заказчик не знает Rust, поэтому всё расписывается понятным языком.

### Правило 6. Обновление документации после каждого этапа (ОБЯЗАТЕЛЬНО)
По завершении каждого таска/этапа обновляются ВСЕ затронутые md-файлы:
- **корневой [README.md](../../README.md)** — таблица статуса модулей, навигация, при необходимости граф архитектуры;
- **[учебный журнал](03_dev_journal.md)** — новый раздел с подробным разбором «что/зачем/почему» простым языком;
- **[архитектурный план](00_architecture_plan.md)** — если менялись решения.

Требования к качеству md:
- все md красивые и информативные (заголовки, таблицы, эмодзи-маркеры, диаграммы Mermaid);
- из корневого README — рабочие ссылки на все внутренние документы;
- учебные документы — максимально подробные (расчёт на человека, не знающего Rust).

## Шаблон сообщения коммита

```
<этап>: <краткая суть>

- что сделано пункт 1
- что сделано пункт 2

Проверено вручную: <да/нет>
```

Пример:
```
Этап 1: инициализация Cargo-проекта и автопроверки CI

- добавлен Cargo.toml с метаданными проекта
- добавлена заглушка src/main.rs (выводит приветствие)
- настроен .github/workflows/ci.yml (fmt + clippy + test)
```
